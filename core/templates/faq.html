1 Tournament Data & Coverage #

Is the Magic Online Challenge data complete? #

Daybreak Games (the studio operating MTGO) typically publishes only the top 32 decks from Magic Online Challenges, regardless of total tournament players. Whether a Challenge draws 64, 128, or 250+ players, only the top 32 decklists and standings are published in the official MTGO tournament results dumps.

Because finishes below 32nd place are omitted from official results dumps, our Challenge Share and metagame metrics reflect only these top 32 lists. Decks that finish outside the top 32 are effectively invisible to {{ SITE_NAME }}. Some analyses like the Legacy Data Collection Project attempt to capture a more complete picture with painstaking work (support them!), but {{ SITE_NAME }} only uses the official published results.

What about Preliminaries and Last Chance Qualifiers (LCQs)? #

Preliminaries (usually 4-round events) and Last Chance Qualifiers (LCQs) are largely excluded from {{ SITE_NAME }}'s metagame statistics because there are relatively few of them in the dataset. While we ingest these events for tournament and player records, they are excluded from Challenge and League share metrics.

How do League 5-0 decks work? #

Daybreak publishes decks that achieved a 5-0 match record in constructed Leagues. Our League Share metric counts the number of 5-0 decks published for each archetype over the total 5-0 league decks. However, decks that don't achieve a 5-0 are not published, so we don't have visibility into the total number of league decks played.

Will you expand to cover paper events? #

Never say never, but probably not. The MTGO dataset is already cleaned (virtually no invalid cards, consistent player names) and pre-processed. There's also a clear hierarchy of the competitiveness of the events (Challenges > Leagues). Even though paper events are in the decklist cache we're using (from Melee.gg), it would be a lot of work to cover them and MTGO by itself gives a pretty clear idea of the current metagame.

Can you add <Feature>? #

Create an issue to discuss how the feature would fit into the site. If it fits with the data {{ SITE_NAME }} already has and it's useful across formats, I'll probably add it.

Can I explore the data behind {{ SITE_NAME }} myself? #

The data for {{ SITE_NAME }} is built entirely from public sources: Scryfall card data and a cache of MTGO tournament results.

You can also download the exact database dump (~800 MB) used to serve {{ SITE_NAME }}. It's an SQLite database that can be opened with standard tooling.

2 Metagame Metrics Explained #

Challenge Share #

The percentage of all published Challenge decks (typically 32 per event) represented by a given archetype within the selected timeframe. Reflects competitive adoption at the premier tournament level.

Top 8 Share #

The percentage of total available Top 8 playoff spots (8 × challenge_count) captured by this archetype. High Top 8 Share indicates high absolute tournament success.

Conversion Rate #

Calculated as Top 8 Finishes / Challenge Appearances. Measures an archetype's win efficiency: when a player brings this deck, how likely are they to convert their run into a Top 8 appearance? Since there are usually only 32 decklists posted per challenge, a conversion rate significantly above 25% (8 / 32) is very good.

League Share #

The proportion of all verified League 5-0 trophies earned by an archetype within the selected timeframe. While Challenges represent premier competitive play, League Share reflects everyday popularity, accessibility, and brewing viability.

3 Classification & Color Inferences #

How does {{ SITE_NAME }} identify archetypes and colors? #

Decklists are processed through a multi-stage classifier:

  1. Curated Signatures: Formats define archetype signatures with mandatory cards, minimum signature card thresholds, and anti-signatures (cards that exclude a deck from an archetype, like preventing Delver lists with Bowmasters from matching Izzet Delver). The archetype signatures are public. You can read more about them in our repository or use them yourself.
  2. TF-IDF & k-Nearest Neighbors (kNN): Unclassified decks are matched against known archetypes using TF-IDF cosine similarity with recency decay. Decks that don't match the curated signatures perfectly but are "close" get classified as the same archetype.
  3. True Color Deductions: Color identities are inferred by examining whether the deck's mana base (lands and permanent mana producers) can produce the colors required by its castable spells. Free pitch spells/cards (Faerie Macabre) and Phyrexian mana (Dismember, Surgical Extraction) do not count toward a deck's color identity. Decks not classified by the curated signatures or nearest neighbor get tagged as "Abzan Midrange" or "Grixis Control".

If you think a certain classification could be improved (without becoming too specific or brittle), feel free to create an issue or pull request.

4 About #

What does {{ SITE_NAME }} do that other aggregators don't? #

{{ SITE_NAME }} was built because the existing deck aggregators like MTGGoldfish and MTGTop8, while powerful and with features {{ SITE_NAME }} won't ever have, don't do the kind of deeper analysis on archetype strength I wanted to see. Specifically, I wanted Challenge conversion rates and separated League and Challenge play rates.
